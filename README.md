# Explainable Agentic AI for Solid Rocket Motor Design and Post-Fire Diagnostic Reasoning

PID 7 | Team: Keya Chembuli, Uppu Shivapratheek (AI/ML) | Mirza Ubaidullah Baig, Hari Shreyas (Mechanical)

Two connected agents over a shared physics/simulation layer:
- **Design Agent** - given performance/safety targets, proposes grain geometries using
  tool-grounded physics equations and a surrogate-accelerated OpenMotor bridge, with
  transparent justification for each choice.
- **Diagnostic Agent** - compares real static-fire telemetry against predicted
  performance curves and generates ranked, evidence-cited failure hypotheses via RAG
  over propulsion failure-mode literature.

## Repo structure

```
simulator_bridge/    openMotor (motorlib) wrapper - params in, thrust/Pc/Kn curves out
structural_tools/    Ported mech-team equations: hoop stress, bulkhead bending, port/throat ratio
surrogate/           GBM models trained on (params -> curve) pairs generated by simulator_bridge
design_agent/        Design Agent: propose -> score via surrogate -> validate -> explain
diagnostic_agent/    Diagnostic Agent: telemetry vs. prediction -> RAG-grounded failure hypotheses
orchestration/       LangGraph/FastAPI glue tying the agents together
data/raw/            Generated (params -> curve) simulation pairs, static-fire telemetry
data/processed/      Cleaned/featurized data for surrogate training
literature/          Paper survey collection + summaries
docs/                Proposal docs, slide content, base paper notes, equation reference
scripts/             One-off validation / data-generation scripts
test/                Unit tests
```

**Phase 2 (Surrogate + Design Agent) - in progress**

- [x] Surrogate model trained (`surrogate/train_surrogate.py`) - GradientBoostingRegressor
      per output (thrust, impulse, pressure, Kn), R^2 0.96-0.98, ~3000x faster than the
      real simulator (~2ms vs ~6s per prediction).
- [x] Surrogate review tooling (`surrogate/review_surrogate.py`, `surrogate/plot_training_data.py`) -
      feature importance, residuals, cross-validated R^2, error-vs-data-density checks, plus
      exploratory plots of the training set.
- [x] Design Agent search, three versions kept side by side for comparison:
      - `design_agent/search_v1_random.py` - brute-force random sampling (20,000 candidates)
      - `design_agent/search_v2_de.py` - differential evolution (global search), ~half the
        evaluations of random search for an equal-or-better result
      - `design_agent/search_v3_hybrid.py` - DE followed by Nelder-Mead local refinement.
        Note: SLSQP (gradient-based, matching the Nisar et al. paper's SQP approach) was
        tried first and found to silently fail, GBM surrogates produce a piecewise-constant
        prediction surface, so finite-difference gradients are usually exactly zero.
        Nelder-Mead (gradient-free) is the correct pairing for a tree-based surrogate.
- [x] Four grain types, each with a simulator wrapper (`simulator_bridge/`), a data generator
      (`scripts/generate_sweep_data_*.py`) and a surrogate with physics features and a
      range-guarded `predict(params, fallback=True)` (`surrogate/*_surrogate.py`) that runs the
      real simulator for designs outside the training ranges:
      - BATES (`bates_motor.py`)
      - Finocyl (`finocyl_motor.py`)
      - BATES + Finocyl hybrid, Finocyl segment forward (`hybrid_motor.py`)
      - Star (`star_motor.py`) - trained on 1,326 clean sims out of 2,000; R^2 0.997-0.998 on
        400 separately generated sims (`train_star_surrogate.py --holdout`), matching its
        test-split R^2, so no sign of overfitting.
      The BATES surrogate is trained on all successful sims, alert-flagged ones included; the
      other three drop flagged sims (except the tail-off flow-separation warning every
      Finocyl/Star design trips).
- [x] Latin hypercube training data (`scripts/generate_sweep_data_lhs.py`) - 5,000 LHS samples
      per grain type (plus a separate 500-sample holdout), with every sim's full
      thrust/pressure/Kn curve kept in a `_curves.jsonl` sidecar for future whole-curve
      surrogates. All four surrogates are retrained on it. On the shared 500-sample holdout
      (`surrogate/compare_surrogates.py`), mean impulse error vs the previous random-sample
      models: BATES 2.21% -> 0.95% (500 -> 5,000 sims), Finocyl 1.95% -> 1.21%, Hybrid
      1.38% -> 0.89%, Star 1.47% -> 0.95%; every target improves for every grain, and the
      p95 errors drop by 35-65%. Part of the gain is the larger sample count, not only the
      sampling method.
- [x] Multi-grain search (`design_agent/search_multigrain.py`) - runs the v3 DE + Nelder-Mead
      search for all four grain types through each grain's range-guarded surrogate,
      re-simulates each grain's pick for real and ranks the grains on the real results.
      Fallback simulations whose real result raises an alert are penalized, otherwise the
      exact fallback draws the optimizer into flagged designs. At 1300 Ns / 6 MPa: BATES
      1298.5 Ns, Finocyl 1276.8 Ns, Star 1270.6 Ns in the real simulator; the Hybrid's pick
      tripped the mass-flux limit and was flagged.
- [x] Multi-grain K-class sweep (`design_agent/kclass_sweep_multigrain.py`) - the K-class sweep
      for all four grain types against the real K950 curve (9 targets each). Best valid thrust
      cosine similarity: BATES 0.9936, Hybrid 0.9923, Star 0.9918, Finocyl 0.9908 - a spread
      smaller than the variation between neighbouring targets for one grain, so no grain type
      is meaningfully better on this metric. Now ranked by the absolute thrust match error
      below instead.
- [x] Curve-shape validation (`design_agent/curve_matching.py`) - cosine similarity +
      relative impulse error against a target pressure/thrust curve (Eqs. 35-36, Fan et al.
      2026). Requires the real simulator, since the surrogate only predicts scalar peaks,
      not full curves.
- [x] Absolute curve-match scoring (`curve_matching.thrust_match()`, tests in
      `test/test_curve_matching.py`) - replaces cosine similarity for ranking. Error =
      normalized RMSE of thrust over the burn (divided by the target's average thrust) +
      0.5 x |impulse error| + 0.5 x |burn time error|; lower is better, 0 = identical. Weights
      are fixed a priori, not fitted to any target. Cosine is still reported. On K950, 339
      eligible library designs score cosine >= 0.99 while their impulse ranges from -86% to
      +56% of the target; the top cosine pick is 68% short on impulse.
- [x] Match any target curve (`design_agent/match_curve.py`) - screens all ~22,000 saved LHS
      curves (four grains, training + holdout) against the target in seconds, excluding
      alert-flagged, structurally failing or over-pressure designs, then refines the best
      per grain with Nelder-Mead on the real simulator (40 sims each by default). Impulse,
      burn time and level all come from the target curve, so nothing is target specific.
      K950 at 6 MPa: Finocyl 0.099 (impulse +0.4%, burn time +3.6%), Hybrid 0.104, Star 0.114,
      BATES 0.148. Also run on four synthetic non-K950 targets (regressive ~600 Ns,
      boost-sustain ~1200 Ns, progressive ~1800 Ns, short neutral ~2500 Ns): best errors
      0.09-0.27, with refinement improving every grain's library pick.
- [x] Result plotting (`design_agent/plotting.py`) - single combined-axis chart (Kn,
      Pressure, Force) matching OpenMotor's own GUI plot style, plus a stats readout.
- [x] Structural checks (`structural_tools/casing.py`, write-up in `docs/structural_checks.md`):
      Lame thick-wall case stress (von Mises, closed ends), Barlow burst, flat-plate
      bulkhead bending and radial-bolt closure retention (shear, bearing, tear-out, net
      tension) at the design's peak pressure. Verified against force equilibrium, the
      thin-wall limit, Roark's plate coefficients and a hand-worked example
      (`test/test_structural.py`). Wired into the multi-grain search (penalty during search,
      FLAGGED pick if the real sim fails) and the K-class sweep, and recorded as columns in
      the LHS sweeps. Case hardware defaults are placeholders until the mech team supplies
      theirs.

## Known limitations

- `motorlib`'s internal ballistics model is quasi-steady-state (0-D): pressure/thrust are
  recomputed from the instantaneous burning surface area at each timestep, with no chamber
  gas-dynamics ODE. This means burnout is a hard cutoff (thrust drops from near-peak to
  exactly 0 in one timestep), not a physical tail-off decay. Documented as a known
  simplification for now; a synthetic decay tail for visualization/curve-matching purposes
  is a possible future addition, not yet implemented.
- The surrogate is measurably (though only mildly) less accurate in sparser regions of the
  sampled design space, which matters most near constraint boundaries (high pressure, tight
  port/throat ratios) where the optimizer tends to push designs. Oversampling those regions
  in future data generation is a noted improvement, not yet done.
- Curve matching works on real simulated curves (library screen + real-sim refinement), not
  the surrogates, which only predict scalars. Refinement is local and capped, so it improves
  the best library design rather than searching globally; a whole-curve surrogate trained on
  the `_curves.jsonl` sidecars would allow a global curve search. No design reproduces
  K950's ignition spike and dip, and the simulator's propellant (KNSU) differs from K950's
  (APCP), so a perfect match is not expected.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt

# openMotor's motorlib is not vendored in this repo (GPLv3, separate project) - clone it
# alongside this repo and point PYTHONPATH at it:
git clone https://github.com/reilleya/openMotor
# build its Cython extension once:
cd openMotor && python setup.py build_ext --inplace && cd ..
# then, whenever running anything that imports motorlib:
export PYTHONPATH=/path/to/openMotor      # Windows: $env:PYTHONPATH = "..."
```
